# T012：Sv39 walker、隐式 PTE 访问与 SFENCE.VMA

状态：verified（2026-10-12）。依赖 T011 verified（c155c62）。持续总目标，不在本阶段停止。

固定 Priv-v1.12 supervisor 的 Sv39/translation algorithm，PA56、ASIDLEN=0，
支持 Bare/Sv39，硬件精确更新 A/D。4K/2M/1G、canonical VA、PTE V/R/W/X/U、
reserved63:54、nonleaf U/A/D、superpage 对齐、SUM/MXR 与 MPRV；fault tval 为原 VA。
页表读写以 S 权限检查 PMP，全宽 8-byte、只允许 RAM PMA；错误返回原访问类型
access fault。有效叶子的 A/D 更新在最终数据 PMP 检查前，失败可能保留该隐式效果。
单 hart、无并行 DMA，在一次执行边界内 PTE 检查与全宽写不可被另一执行器插入。

先实现无 TLB walker；SFENCE.VMA 检查 S/U/TVM，合法执行满足完整失效语义。
支持保守全失效，无 ASID cache。satp 只接受 MODE0/8，ASID=0，PPN44；unsupported
MODE 整次写忽略。Sv39 硬件 Bare MODE 时保留 PPN（规范允许的 UNSPECIFIED 选择），
旧 Bare-only 硬件 hardwired satp=0。硬件能力由 CONFIG_RV_SV39 默认和初始化 API
选择，独立工具共同输入 mmu bare|sv39 在执行前同时配置两端；旧 fixture 明确 Bare。
完成闭环后 misa 才加入 S/U，不增加 F/D 或其它未完成能力。

真实引擎验收：虚拟 fetch/load/store/LR/SC/AMO、跨页 C/I 与第二 halfword fault，
delegation/xRET、page/access 分类、A/D RAM 变化、PMP PTW read/write 拒绝、权限和
非法 PTE、satp WARL、SFENCE 及页表修改/切换。独立固定 Spike 保持无源码补丁，
只观察实际 fetch/store；全 RAM hash 包含 PTE 副作用，不主动翻译获取观察数据。
规范常量 unit、确定性生成矩阵、fresh-process replay、3 种差异注入、UBSan，
minimal/MAC+PMP/Sv39 配置回归。保留首失败，不修改期望或放宽比较。

完成继续 T013 F/D，然后 virt 设备、固定 OpenSBI/Linux 和重复 workload。


首差异：docs/validation/t012_first_failure.json，固定 Spike 默认 A/D fault。
初始化参考 ISA 加 Svadu、menvcfg.ADUE=1 以选择 Priv1.12 硬件更新策略；共同
程序不使用新的 CSR/指令，RVISS 不宣称 Svadu。第二差异 t012_satp_failure.json：
Spike set_mmu_capability(SV39) 没清除 constructor 默认 Sv48/Sv57。先 SBARE 清除、
再开启 Sv39；完整 virtualized_satp 调用链遵守 unsupported MODE 整写忽略，
无规范兼容源码补丁，原始官方源码保持不变。两个失败命令退出 1，比较字段保留。
